# UX/UI Design Specification — WealthLens

**Version:** 1.1.0  
**Last Updated:** 2026-07-13  
**Design Philosophy:** *Data tells a story. Our job is to make that story beautiful, clear, and actionable.*

---

## 1. Design Principles

### 1.1 Clarity Over Cleverness
ทุก element บน screen ต้องตอบคำถามว่า "มันช่วย Tom เข้าใจการเงินของตัวเองได้ยังไง?" ถ้าตอบไม่ได้ → ตัดออก

### 1.2 Data-First Design
ตัวเลขคือ hero ของ design นี้ ดังนั้น typography ต้องรองรับการอ่านตัวเลขได้สบายตา ทั้งเล็กและใหญ่

### 1.3 Calm & Trustworthy
สีและ mood ต้องให้ความรู้สึกว่า "ระบบนี้จัดการได้ มีเสถียรภาพ" ไม่ใช่ panic-inducing

## 7. Interaction Design

### 7.1 Data Entry UX
- **Tab to navigate** ระหว่าง input fields
- **Auto-format** ตัวเลขเป็น comma-separated ขณะพิมพ์
- **Inline validation** แสดง error ทันทีที่ blur จาก field
- **Keyboard shortcut:** `Ctrl+S` / `Cmd+S` เพื่อ save

### 7.2 Chart Interactions
- **Hover tooltip** แสดงตัวเลขละเอียดเมื่อ hover
- **Click legend** เพื่อ toggle series visibility
- **Responsive** resize ตาม viewport

### 7.3 Year/Month Navigation
- **Year Selector:** Dropdown ที่ Header
- **Month Navigation:** Prev/Next arrows ใน Monthly Detail
- **Breadcrumb:** ปี > เดือน

### 7.4 Empty States
- ถ้าไม่มีข้อมูลเดือนนั้น → แสดง "ยังไม่มีข้อมูล กด + เพื่อเพิ่ม"
- ถ้า expenses = 0 → แสดง "เพิ่มค่าใช้จ่ายของเดือนนี้"

## 8. Responsive Breakpoints

เส้นแบ่งจริงมีเส้นเดียวคือ `md:` (768px) — ต่ำกว่านั้นคือ "มือถือ" (แถบล่าง + ปุ่มลอย, ไม่มี sidebar), ตั้งแต่นั้นขึ้นไปคือ "เดสก์ท็อป" (sidebar 240px, ไม่มีแถบล่าง/ปุ่มลอย) ดูรายละเอียดที่ §12

## 9. Accessibility

- **Color contrast:** ทุก text ต้อง pass WCAG AA (4.5:1 ratio)
- **Focus states:** ทุก interactive element ต้องมี visible focus ring
- **ARIA labels:** ทุก chart ต้องมี aria-label อธิบาย
- **Keyboard navigation:** ทั้งหมดต้องใช้ keyboard ได้
- **Modal ขังโฟกัสไว้ในกรอบ (F49):** Tab / Shift+Tab **วนอยู่ในแผง** ตราบใดที่ป๊อปอัพเปิดอยู่ (เดิมโฟกัสไหลออกไปโดนปุ่มที่อยู่ *ข้างหลัง* ป๊อปอัพ — คนใช้เมาส์ไม่มีทางรู้ คนใช้คีย์บอร์ดเจอทุกครั้ง) และเมื่อปิด **โฟกัสกลับไปที่ปุ่มที่เปิดมัน** ไม่ใช่เด้งไปต้น `<body>` ให้ต้อง Tab ใหม่ทั้งหน้า. ESC ปิดได้เหมือนเดิม; `aria-hidden` ยัง **จงใจไม่ใส่** บน wrapper (แผงยังอยู่ระหว่างเล่น exit animation ตอนคืนโฟกัส — `aria-hidden` คร่อม element ที่โฟกัสอยู่คือการผิด a11y เสียเอง)

## 11. Color Tokens & Dark Mode (F46 — shipped 2026-07-13)

> บล็อก dark ที่เคยเขียนเผื่อไว้ในหัวข้อนี้ **ไม่เคยทำงานเลย** — selector เป็น `:root.dark` ซ้อนอยู่ใน `@media (prefers-color-scheme: dark)` คือต้องทั้ง OS มืด **และ** มี class `.dark` ที่ไม่เคยมีใครใส่ให้ `<html>` สักครั้ง. F46 รื้อทิ้งแล้วทำของจริง

### 11.1 หลักการ — ค่าจริงอยู่ที่เดียว โค้ดที่เหลืออ้างชื่อ

```
src/index.css        ← ค่าสีจริงทั้งหมด (:root = สว่าง, .dark = มืด)
tailwind.config.js   ← ชื่อ token ชี้ไป rgb(var(--x) / <alpha-value>)
component            ← อ้างชื่อ token เท่านั้น ไม่รู้จักค่า hex
```

**เก็บเป็น "เลขช่องสี" ไม่ใช่ hex:** `--bg-card: 255 255 255;` — ถ้าเก็บเป็น `#ffffff` แล้วเขียน `bg-card/60` มันจะ**เงียบและไม่ทำงาน** (Tailwind ประกอบ alpha ไม่ได้)

**กฎเหล็ก:** โหมดสว่างต้องไม่ขยับแม้แต่พิกเซลเดียว — ค่าสว่างของทุก token = ค่า Tailwind ขั้นเดิมเป๊ะ ตรึงด้วย **R0** ใน `scripts/verify-theme.ts` (324 assertions). ห้ามเขียนสีดิบใน component — `scripts/verify-no-hardcoded-colors.ts` เป็นประตูกัน (allowlist ว่าง; ยกเว้นแค่ `text-white` ที่นั่งบนพื้นสีอิ่มตัว)

### 11.2 สีหนึ่งมี "สองบทบาท" — แนวคิดที่รับน้ำหนักทั้งงานนี้

`--color-primary` เดิมถูกใช้สองบทบาทที่ต้องการค่า **ตรงข้ามกัน** ในโหมดมืด:

| บทบาท | ตัวอย่าง | โหมดมืดต้องการ |
|---|---|---|
| **พื้น (fill)** — มี `text-white` ทับ | `bg-primary text-white` | **เข้มเท่าเดิม** ไม่งั้นตัวขาวบนปุ่มอ่านไม่ออก |
| **หมึก (ink)** — บนการ์ด | `text-primary`, `border-primary` | **สว่างขึ้น** ไม่งั้นจมหายไปกับการ์ดมืด |

จึงแยกชื่อตามบทบาท ทำเหมือนกันทั้ง **5 ตระกูล**: `primary`←blue · `income`←emerald · `expense`←red (rose ยุบเข้ามา) · `warning`←amber (savings ใช้ชุดเดียวกัน) · `net`←violet

| token | ใช้กับ | light | dark |
|---|---|---|---|
| `<f>` (DEFAULT) | `bg-*` พื้นปุ่ม | สี 600 เดิม | **เท่าเดิม** |
| `<f>-fill` | แถบ progress (`bg-*-500` เดิม) | สี 500 เดิม | **เท่าเดิม** |
| `<f>-dark` | `hover:bg-*-700` | สี 700 เดิม | **เท่าเดิม** |
| `<f>-ink` | `text-*` / `border-*` / `ring-*` บนการ์ด | สี 600 เดิม (**ไม่ขยับ**) | สี 400 (สว่างขึ้น, ≥4.5 บนการ์ด) |
| `<f>-{50,100,200,300}` | พื้น/ขอบ chip | Tailwind เดิม | กลับด้าน (ผสมสีการ์ดแล้ว ไม่ใช่สีอิ่มตัวดิบ) |
| `<f>-{700,800,900}` | ตัวหนังสือใน chip | Tailwind เดิม | กลับด้าน |
| `<f>-on-fill` | ตัวหนังสือที่นั่งบนพื้นสี | สี 300 | **เท่าเดิม** |

> จุดสวย: **สี 600 ของ Tailwind = สีแบรนด์เดิมพอดีทุกตระกูล** (`emerald-600` = `#059669` = income เป๊ะ) → `text-emerald-600` → `text-income-ink` แล้วโหมดสว่างไม่ขยับแม้แต่บิตเดียว

### 11.3 neutral ramp — `ink-100…900` (ใช้ทั้ง text และ border)

ค่าโหมดสว่าง = ค่า `slate-*` เดิมเป๊ะทุกขั้น (ห้ามยุบ 600 กับ 700 เข้าด้วยกัน — ตาเห็นต่าง). ค่าโหมดมืด **ไม่ใช่การกลับด้านตรง ๆ** แต่เลือกแล้ววัด contrast จริงทุกขั้น

| token | light | dark | ใช้แทน |
|---|---|---|---|
| `ink-900` | `#0F172A` | `#F8FAFC` | ตัวหนังสือหลัก |
| `ink-500` | `#64748B` | `#94A3B8` | เนื้อความรอง (จุดที่ใช้เยอะสุด) |
| `ink-400` | `#94A3B8` | `#64748B` | ป้ายจาง |
| `ink-300`…`ink-100` | `#CBD5E1`…`#F1F5F9` | `#475569`…`#28354A` | ขอบการ์ด / เส้นคั่นตาราง |

### 11.5 เลือก token ยังไง

1. เป็นตัวหนังสือ/เส้น ที่ไม่มีความหมายเชิงตัวเลข? → `ink-*` (เข้ม = สำคัญ)

5. เป็นกราฟ? → **ห้ามใช้ token** — `useChartTheme()` เท่านั้น (Recharts ยัดสีลง SVG presentation attribute ซึ่งสเปกไม่รับ `var()` เขียนไปเส้นจะหายเงียบ ๆ ไม่มี error)

### 12.2 เมนูอยู่ล่าง ไม่ใช่มุมซ้ายบน

นิ้วโป้งข้างเดียวเอื้อมถึงครึ่งล่างของจอ 6 นิ้ว — **แฮมเบอร์เกอร์มุมซ้ายบนคือมุมที่ไกลที่สุดพอดี** (และมันกิน 40px จาก header จนชื่อหน้าโดนตัด) แฮมเบอร์เกอร์ + drawer จึงถูก**ลบทิ้ง** ไม่ใช่ย้าย

- **`BottomNav`** (`md:hidden`) — 5 ช่อง: **ภาพรวม · รายเดือน · บัญชีธนาคาร · วิเคราะห์ · อื่นๆ**

  - `<main>` ได้ `pb-24` บนมือถือ ไม่งั้นเนื้อหาท้ายหน้าถูกแถบทับ
- **`AddFab`** (`md:hidden`) — ปุ่มลอย "+" มุมขวาล่างเหนือแถบล่าง → `/monthly?add=expense` แล้ว `MonthlyPage` สั่ง `ExpenseList` เปิดฟอร์ม**รายจ่าย**ให้ทันที (งานที่ทำบ่อยสุดบนมือถือ — ไม่ต้องถามก่อนว่าจะเพิ่มอะไร) แล้วล้าง query param ทิ้ง ไม่งั้น refresh/ย้อนกลับฟอร์มเด้งซ้ำ

### 12.3 พื้นที่กด 44px — และข้อยกเว้นต้องมีเหตุผล

ทุก control ที่กดจริง (`button` / `a` / `select` / checkbox) ต้องสูง ≥ **44px** (Apple HIG) **เฉพาะบนมือถือ**: `min-h-11 md:min-h-0` (ปุ่มไอคอนใช้ `min-h-11 min-w-11 md:min-h-0 md:min-w-0` + `inline-flex` จัดกลาง) — เดสก์ท็อปจึงไม่อ้วนขึ้นแม้แต่พิกเซลเดียว

**ยกเว้นได้ ถ้าเขียนเหตุผลกำกับ** — ติด `data-tap-exempt` แล้ว `verify:mobile` จะข้ามให้. วันนี้มี **4 จุด เหตุผลเดียวกันทั้งหมด**: กล่องติ๊ก native บนหน้าภาษี ขยายเป็น 44px ไม่ได้โดยไม่บวมเสียรูป — `<label>` ที่ห่อมันอยู่ต่างหากคือพื้นที่กด 44px จริง (พิสูจน์แล้วด้วยการกดที่ตัวอักษรของ label ห่างจากกล่องติ๊ก แล้วมันติ๊กจริง). ถ้าวันไหนข้อยกเว้นเกิน 3–4 จุด แปลว่ากำลังโกงประตูตัวเอง

### 12.4 ตารางกว้าง — ตรึงคอลัมน์แรก ไม่แตกเป็นการ์ด

การ์ดรายเดือนอ่านง่ายทีละใบ แต่ **เทียบข้ามเดือนไม่ได้อีกเลย** ซึ่งเป็นเหตุผลเดียวที่ตารางพวกนี้มีอยู่ (หลักเดียวกับกฎ "ตัวเลขในตารางมีไว้เทียบกัน จึงไม่มีเลขวิ่ง" ใน §10/CLAUDE.md) — ตารางจึงยังเป็นตาราง แค่มีที่ยึด

ทำกับ 5 ตาราง: `MonthlySummaryTable` · `AllYearsSummary` · `MultiYearComparison` · `LoanScheduleTable` · `PaymentLogTable`

กติกาสองข้อที่ทำให้มันไม่พัง:
1. **เซลล์ที่ตรึงต้องพื้นทึบ** ไม่งั้นตัวเลขที่เลื่อนอยู่ข้างหลังทะลุขึ้นมาให้เห็น
2. **ต้องเป็นสีของ "แถวตัวเอง"** (`bg-inherit` บนเซลล์ แล้วตั้งสีที่ `<tr>`) ไม่ใช่ `bg-card` ตายตัว — ไม่งั้นแถวรวม / แถวงวดปัจจุบัน (เขียว) / zebra จะมีตะเข็บสีผิดพาดขอบซ้าย. แถวที่เคยโปร่ง (`bg-surface/60` ฯลฯ) จึงถูกแปลงเป็น `color-mix` สีเดียวกันเป๊ะแต่ทึบ

> **ต้นทุนที่รู้และยอมจ่าย:** แถว "ยอดรวม" ของ `LoanScheduleTable` เดิมเป็น `colSpan={3}` — ตรึงทั้งก้อนจะได้บล็อกอ้วนบังยอดที่เลื่อนผ่านใต้มัน จึงแยกเป็นเซลล์ label (ตรึง) + `colSpan={2}` ว่าง **ผลคือคอลัมน์แรกของตารางนี้ตารางเดียว กว้างขึ้นบนเดสก์ท็อป 85 → 106px** (ความกว้างตารางรวม ความสูงแถว ความสูงหน้า เท่าเดิม) — ที่เหลือทั้งแอปเดสก์ท็อปเหมือนเดิมทุกพิกเซล

### 12.5 ความหนาแน่น — และผลจริงที่ได้

- **KPI 2×2 บนมือถือ** (`grid-cols-2 … lg:grid-cols-4`) — เดิม 4 ใบเรียงเต็มความกว้าง = เลื่อนสองจอกว่าจะเจอเนื้อหา. ตัวเลขยาว (`฿2,598,100`) ย่อ type เป็น `text-xl md:text-3xl` — **ห้ามใช้ `truncate` กับตัวเลขเงิน ตัวเลขที่ถูกตัดคือตัวเลขที่โกหก** (วัดแล้วกว้าง 113px ในกล่อง 139px)
- **กราฟเตี้ยลง 20% เฉพาะมือถือ** ผ่าน `src/utils/chartSizing.ts` — `<ResponsiveContainer>` ต้องการ parent ที่มีความสูงคงที่ (ไม่งั้นยุบเหลือ 0) แต่ความสูงเป็น prop ซึ่ง Tailwind อ่านค่า runtime ไม่ได้ จึงส่งเป็น CSS custom property แล้วให้ class คิดเลข: `h-[calc(var(--chart-h)*0.8)] md:h-[var(--chart-h)]` — เดสก์ท็อป 320/320/340px เท่าเดิมทุก px

**ผลที่วัดได้ (ไม่ใช่ที่แผนเดา):** `/` 3,470 → **2,959px (−14.7%)** — แผนเดาไว้ ~25% แต่เลขของแผนเองรองรับแค่ ~16%. `/analytics` 6,746 → **6,584px (−2.4%)** เท่านั้น เพราะความยาวของหน้านั้นมาจาก anomaly panel + subscriptions + comparison ไม่ใช่กราฟ — ถ้าอยากให้สั้นกว่านี้ต้องไปแก้ที่โครงของหน้า ไม่ใช่ที่ความสูงกราฟ

`/wealth` (F38) บอกได้แค่ **ตัวเลข ณ วันนี้** — สเปกของมันเองเขียนไว้ว่ากราฟย้อนหลังคืองานอีกชิ้น. หน้านี้คืองานชิ้นนั้น: `/wealth` ตอบ *"วันนี้เท่าไร"*, `/growth` ตอบ *"มาถึงตรงนี้ได้ยังไง"*

### 13.1 หัวหน้า (hero)

ความมั่งคั่งสุทธิเดือนล่าสุด (เลขวิ่งได้ — เป็น hero ตามกฎ §10) + **% เทียบเดือนก่อน** — แต่ถ้าเดือนนั้นเป็น "จุดเริ่มติดตามบัญชีใหม่" จะพิมพ์ **"เทียบไม่ได้ (เริ่มติดตามบัญชีใหม่)"** แทนตัวเลข ไม่ใช่ซ่อนบรรทัดนั้นเงียบ ๆ. ใต้ตัวเลขมีป้าย "ไม่รวมมูลค่าบ้านและรถ" เหมือน `/wealth` — และมันคือ**ตัวเลขเดียวกันเป๊ะ** (บังคับด้วย G1 ใน `scripts/verify-growth.ts`: จุดสุดท้ายของอนุกรมต้องเท่ากับ `computeNetWorth()` ที่ `/wealth` ใช้ — เครื่องคำนวณสองตัวไม่ตรงกัน = ผู้ใช้เห็นความมั่งคั่งสองค่าในแอปเดียวแล้วไม่มีทางรู้ว่าอันไหนจริง)

### 13.2 กราฟความมั่งคั่งย้อนหลัง — คำเตือนอยู่หลังข้อมูล ไม่ใช่ทับมัน

Area chart ของ `netWorth` รายเดือน (ม่วง `#7C3AED` + gradient จาง — สีตระกูล net เดิม), ป้ายเดือนไทยย่อ, แกน Y เป็น ฿k

ก.ค. 2026 Tom **เพิ่งเริ่มบันทึก 5 จาก 6 บัญชี** พร้อมกัน (เงินสดก้อนเดียว ฿150,000) เส้นจึงกระโดด — **ทั้งที่เงินนั้นมีอยู่มาตลอด เขาแค่เริ่มนับมัน** กราฟจึงต้องพูดออกมาสามทาง:

1. **หมุด `<ReferenceDot>`** ทุกเดือนที่มีบัญชีใหม่โผล่ครั้งแรก — tooltip บอกชื่อบัญชีที่เริ่มติดตาม
2. **แถบพื้นหลังจาง** (`<ReferenceArea>`, amber 9% opacity) คลุมช่วงที่ยังครอบคลุมบัญชีไม่ครบ + caption ใต้กราฟบอกว่าครอบคลุมกี่จากกี่บัญชี
3. **tooltip** แจกแจง สินทรัพย์ / หนี้ / สุทธิ + เตือนเมื่อทองยังคิดด้วยราคาทุน (`goldIsCostBasis` — ยังไม่รู้ราคาตลาดของเดือนนั้น)

> **บทเรียนที่แพงที่สุดของหน้านี้:** รอบแรกช่วง "ครอบคลุมไม่ครบ" ถูกวาดเป็น **เส้นประ opacity 0.5** ตามสัญชาตญาณว่า "ข้อมูลไม่ครบก็ทำให้มันจางลงสิ" — แต่มันจริงกับ **42 จาก 43 เดือน** คำเตือนจึงกลืนกราฟทั้งใบจนหน้าดูเหมือนไม่มีข้อมูล ทั้งที่เส้นนั้นเล่าเรื่องจริงว่าเงินดีขึ้นหลายล้านใน 3 ปีครึ่ง
>
> **กฎที่ตามมา: ข้อมูลจริงต้องดังที่สุดบนกราฟเสมอ — คำเตือนอยู่ข้างหลังมัน ไม่ใช่ทับมัน** เส้นนี้ไม่ใช่ค่าประมาณ มันคือความมั่งคั่งจริงจากข้อมูลที่มีจริง จึงเป็น**เส้นทึบ เต็ม opacity เส้นเดียว** ส่วนคำเตือนถอยไปเป็นแถบพื้นหลัง + caption

**ไม่มีเส้นทำนายอนาคต** — เราไม่เดา (กฎเดียวกับ "ไม่มี insight ปลอม")

### 13.3 กราฟอัตราการออม — ช่องว่างคือ "ไม่รู้" ไม่ใช่ "ศูนย์"

แท่ง % รายเดือน (เขียว `#34D399` เมื่อบวก, แดง `#F87171` เมื่อ**ติดลบ** = จ่ายเกินรายได้ — **ห้าม clamp เป็น 0**) + เส้นค่าเฉลี่ย 3 เดือน (ม่วง) ที่ `connectNulls={false}`

รายได้ของ Tom ~45% มาจากคอมมิชชั่น — เดือนคอมเยอะกับเดือนคอมน้อยเทียบกันด้วย**ยอดบาท**ไม่ได้เลย ต้องเทียบด้วย **%**

**เดือนที่ไม่รู้ ต้องไม่มีแท่ง** — ปี 2023 ของ Tom มีแต่รายได้ ไม่มีรายจ่ายรายการเลย (data quirk ใน CLAUDE.md) ถ้าคิดว่า "ไม่มีรายจ่าย = จ่าย 0" จะได้อัตราการออม **100% ทั้งปี** แล้วปีที่เรารู้น้อยที่สุดจะกลายเป็นปีที่ Tom **ออมเก่งที่สุด** ในกราฟ. `rate` จึงเป็น `null` และส่ง `null` เข้า Recharts ตรง ๆ ให้มัน**เว้นแท่ง**ไว้ (อย่าแทนที่ด้วย 0) — ค่าเฉลี่ยเคลื่อนที่ก็**ข้าม**ค่า null ไม่นับเป็น 0

caption ใต้กราฟนับให้เห็นว่ากี่เดือนที่ไม่มีข้อมูลรายจ่าย (ปีไหนบ้าง) และกี่เดือนที่ยังไม่มีรายได้ — แยกกันคนละบรรทัดเพราะเป็นคนละเหตุผล — ปิดท้ายด้วยประโยคที่เป็นหัวใจของหน้านี้:

> **ช่องว่างในกราฟคือ "ไม่รู้" ไม่ใช่ "ศูนย์"**

### 13.4 สิ่งที่ไม่ทำโดยตั้งใจ

- **ไม่พยากรณ์ net worth อนาคต** — เดาที่ดูน่าเชื่อถือเกินจริง (เดิมเขียนไว้ว่า "มี `BudgetForecast` สำหรับรายจ่ายอยู่แล้ว" — ตัวนั้นถูกถอดออกใน F50 เพราะไม่มีใครเปิดดู ดู §14)
- **ไม่เทียบกับใคร** — ไม่มีข้อความประเภท "คุณออมได้ดีกว่า 80% ของคนวัยเดียวกัน" เราไม่มีข้อมูลนั้น ไม่มีสิทธิ์พูด
- **ไม่แตะ `/wealth`** — มันตอบคำถามของมันได้ดีอยู่แล้ว

## 14. หน้าวิเคราะห์ (F50 — shipped 2026-07-13)

`/analytics` เคยเป็นเครื่องมือ 6 อย่างคนละเรื่องกองซ้อนกันในหน้าเดียว — **6,584px = 7.8 จอ** ที่ 390px
เปิดมาเพื่อดู *อย่างหนึ่งที่ตั้งใจ* แล้วต้องเลื่อนผ่านอีก 5 อย่างที่ไม่ได้ตั้งใจดู

### 14.1 ตัดของที่ไม่มีใครดูก่อน — แล้วค่อยจัดที่ทาง

36% ของหน้าคือของที่ไม่เคยเปิดดูเลย → **ประมาณการเดือนหน้า (F16) ถูกลบทั้งฟีเจอร์** · **แผงแจ้งเตือนผิดปกติ (F15) ถูกถอด เหลือแต่ toast** (toast มาจาก `useAnomalyAlertEffect` ที่ `Layout` ไม่เคยพึ่งแผงอยู่แล้ว)
การซ่อนไม่ใช่การแก้ — โค้ดที่ยังอยู่คือโค้ดที่ต้องดูแลตลอดไป

### 14.2 สามแท็บ — lazy จริง สถานะอยู่ใน URL

| แท็บ | `?tab=` | มีอะไร | สูงที่ 390px |
|---|---|---|---:|
| **รายปี** (ค่าเริ่มต้น) | `years` | ตารางภาพรวมทุกปี + เทียบข้ามปี | 1,991px |
| **แนวโน้ม** | `trends` | 48 เดือน + สัดส่วนค่าใช้จ่ายตลอดเวลา | 1,297px |
| **Subscription** | `subs` | รายการ + ยอดรวมรายเดือน | 1,502px |

- **lazy จริง ไม่ใช่ `hidden`** — แต่ละแท็บเป็น `React.lazy` แยก chunk และ **แผงของแท็บอื่นต้องไม่อยู่ใน DOM เลย** (กฎ A2). ทะเบียนเก็บ *ตัวคอมโพเนนต์* ไม่ใช่ element ที่สร้างไว้ล่วงหน้า — render เฉพาะตัวที่เลือก
- **สถานะอยู่ใน URL** (`useSearchParams`, `replace: false`) ไม่ใช่ `useState` — ปุ่มย้อนกลับพากลับแท็บก่อนหน้า · บุ๊กมาร์กได้ · ส่งลิงก์ตรงแท็บได้. `useState` ทำไม่ได้สักอย่าง
- `?tab=` ที่ไม่รู้จัก → ตกกลับ `years` **ไม่ใช่หน้าว่าง** (`resolveTab` ใน `src/lib/analyticsTabs.ts` — pure ไม่ import React หลักเดียวกับ `lib/nav.ts`)
- **แถบแท็บ:** pill row ใต้หัวหน้า · แต่ละปุ่ม ≥44px (กฎ F47) · เลื่อนแนวนอนได้บนมือถือ · แท็บปัจจุบันติด `aria-current="page"` · สีจาก token เท่านั้น

**ประตู:** `npm run verify:analytics` (Playwright 390×844) — A1 ทุกแท็บ ≤2,200px · A2 DOM ไม่มีแผงของแท็บอื่น · A3 `?tab=` เป็นแหล่งความจริง · A4 แถบแท็บกดโดน · A5 ไม่ล้นขอบจอ + ประตูกันซากของที่ลบ + toast ของ F15 ต้องยังอยู่

## 15. PWA — ติดจอโฮม · เปิดได้ไม่มีเน็ต (F51 — shipped 2026-07-13)

ครึ่งหนึ่งของ "ออฟไลน์" มีอยู่ก่อนแล้ว: ข้อมูลอยู่ LocalStorage และซิงค์ขึ้น Drive เองตอนกลับมาออนไลน์
สิ่งที่ขาดคือ **ตัวแอปเองเปิดไม่ได้ถ้าไม่มีเน็ต** — งานนี้เติมแค่เปลือก ไม่แตะชั้นข้อมูล

### 15.1 ติดจอโฮม

- **ไอคอน** สร้างจาก `public/favicon.svg` (สายฟ้าม่วง) → 192 · 512 · **maskable 512** · apple-touch 180
  maskable วางโลโก้ใน **safe zone 60%** บนพื้นขาวทึบ — Android ครอบมุมได้ถึง 20% ต่อด้าน โลโก้ที่เต็มกรอบจะโดนตัด
- เปิดจากจอโฮมแล้วเป็น **แอปเต็มจอ** (`display: standalone`) ไม่มีแถบ URL
- **`theme-color` สองค่า** (light `#ffffff` / dark `#0f172a`) — มีค่าเดียวเมื่อไหร่ โหมดมืดจะได้แถบสถานะขาวโพลนคาดอยู่บนหัวแอป
- iOS ไม่อ่าน manifest ครบ จึงต้องมี `apple-touch-icon` + `apple-mobile-web-app-*` ซ้ำใน `index.html`

### 15.2 ออฟไลน์

Service worker (workbox ผ่าน `vite-plugin-pwa`) precache app shell: `index.html` + JS + CSS + ฟอนต์ + ไอคอน + โลโก้ธนาคาร
ตัดเน็ต → เปิดแอป → **เห็นหน้าเดิม ตัวเลขเดิม กรอกรายจ่ายได้** แล้วซิงค์เองเมื่อกลับมาออนไลน์

**สองอย่างที่ไม่มีวันถูก cache** (`NetworkOnly`): `/api/gold-price` (ราคาทองสด — แช่ไว้แล้ว net worth จะคิดจากราคาเมื่อวานโดยไม่มีใครรู้) และ Google Drive/OAuth (token ค้างใน cache = บั๊ก + ความเสี่ยง)
สถานะซิงค์ห้ามโกหก — ออฟไลน์คือ *เขียนได้ แต่ยังไม่ได้ซิงค์* `syncStore` มีสถานะ `offline` อยู่แล้ว

### 15.3 แถบ "มีเวอร์ชันใหม่"

มี SW แล้ว การ deploy ใหม่จะยัง **ไม่** ถึงจอผู้ใช้จนกว่า SW ตัวใหม่จะเข้ามาแทน — ถ้าไม่บอกอะไรเลย ผู้ใช้จะเปิดมือถือ เห็นแอปเวอร์ชันเก่า แล้วสรุปว่า deploy พัง

- แถบเล็กมุมล่าง: `✨ มีเวอร์ชันใหม่` · ปุ่ม **อัปเดต** · ปุ่มปิด — **อยู่จนกว่าจะกด** ไม่หายเอง
  (ไม่ใช้ toast: toast ของโปรเจกต์ไม่มีปุ่มกดและหายใน 4 วินาที — prompt ที่หายเองคือ prompt ที่พลาด)
- **ไม่อัปเดตเงียบ ๆ** — reload กลางคันตอนกำลังกรอกฟอร์ม = สิ่งที่พิมพ์ค้างหาย
- มือถือ: แถบลอยเหนือ **ทั้งแถบล่างและปุ่มลอย "+"** (`bottom-[calc(136px+env(safe-area-inset-bottom))]`) — ไม่งั้นมันบังปุ่มเพิ่มรายจ่ายค้างไว้จนกว่าจะกดปิด. เดสก์ท็อป: มุมขวาล่าง กว้าง 384px

**ประตู:** `npm run verify:pwa` (Playwright 390×844) — P1 manifest/meta · P2 SW + precache · **P3 ตัดเน็ต → reload → dashboard ขึ้นจริง** (ข้อที่ตัดสินทั้งฟีเจอร์) · P4 ออฟไลน์แล้วเพิ่มรายจ่ายผ่าน UI จริงและรอดหลัง reload · P5 cache ต้องสะอาด (ไม่มีราคาทอง/Google) · P6 ทางอัปเดตครบ
