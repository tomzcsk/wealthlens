# F41 — แปลงยอดเก่าเป็นรายการเดินบัญชี (Journal Backfill)

*Design · 2026-07-09*

## 1. ปัญหา

F40 ทำให้ทุกการขยับเงิน **ตั้งแต่นี้ไป** ถูกจดเป็นบรรทัด แต่ยอดที่กรอกไว้ก่อนหน้านั้นไม่มีบรรทัดรองรับ ผลคือ:

- เดือนเก่ากางแล้วเห็นแค่ *"ยอดที่กรอกไว้ ไม่มีรายละเอียดรายการ"*
- เดือน**ผสม** (ยอดเก่า + รายการใหม่) ต้องมีบรรทัดปลอม "ยอดก่อนมีรายการ" มาถ่วงให้แถวรวมตรง
- `findLedgerMismatches` (invariant ของ F40) ถูกบังคับให้ยกเว้นเดือนที่ไม่มีรายการ — กฎจึงตรวจได้ไม่ทั่ว

## 2. เป้าหมาย

เปลี่ยนยอดเก่าให้กลายเป็นรายการจริงหนึ่งบรรทัดต่อ (บัญชี, ปี, เดือน) โดย **ยอดเงินไม่ขยับแม้แต่บาทเดียว** จากนั้นทั้งระบบจะเข้ากฎเดียวกัน: `Σ รายการ = ยอดเดือน` เสมอ ไม่มีข้อยกเว้น

## 3. หลักการที่ทำให้ปลอดภัย

**เครื่องมือนี้ไม่บวกเงิน มันเขียนคำอธิบาย**

สำหรับแต่ละเซลล์ (บัญชี, ปี, เดือน) ที่มียอด:
```
ส่วนต่าง = ยอดของเดือนนั้น − Σ(รายการที่มีอยู่แล้วในเดือนนั้น)
ถ้า ส่วนต่าง ≠ 0 → สร้าง 1 บรรทัด amount = ส่วนต่าง
```
บรรทัดใหม่ถูกเขียน **โดยไม่แตะ `balances`** (ต่างจาก `applyBankMovement` ที่เขียนทั้งสองฝั่ง) เพราะยอดมีอยู่แล้ว เราแค่มาอธิบายมัน

ผลที่ตามมา:
- **นับซ้ำไม่ได้เชิงโครงสร้าง** ไม่ใช่เพราะเราระวัง — ยอดไม่ถูกแตะ จะซ้ำได้ยังไง
- **Idempotent** รันซ้ำ → ส่วนต่าง = 0 → ไม่สร้างอะไร
- **เดือนผสมได้ฟรี** กรุงศรีที่ซื้อทองด้วย Kept: ยอด 5,000 มีบรรทัดทอง −100,000 → ส่วนต่าง +105,000 กลายเป็นบรรทัด "ยอดที่กรอกไว้เดิม"

## 4. ขอบเขต

**In scope**
1. `BankTxSource` เพิ่ม `{ type: 'backfill' }`
2. `utils/journalBackfill.ts` — pure: `planBackfill(ledger)` → รายการบรรทัดที่จะสร้าง (ยังไม่เขียน)
3. store: `applyJournalBackfill()` (เขียน) และ `undoJournalBackfill()` (ลบทุกบรรทัด `backfill`)
4. UI ใน Settings: preview ก่อนกด — "จะสร้าง N บรรทัด ใน M เดือน · ยอดเงินไม่เปลี่ยน" + ปุ่มย้อนกลับ
5. `MonthTransactionList` เลิกต้องคำนวณ "ยอดก่อนมีรายการ" เมื่อบรรทัด backfill มีแล้ว (บรรทัดนั้นทำหน้าที่แทน) — โค้ดเดิมคงไว้เพราะยังต้องรองรับคนที่ยังไม่กดแปลง
6. `scripts/verify-journal-backfill.ts`

**Out of scope (YAGNI)**
- แปลงอัตโนมัติตอน rehydrate — เป็นการแก้ข้อมูลผู้ใช้โดยไม่ขอ ต้องกดเอง
- เดาว่ายอดเก่ามาจากอะไร (เงินเดือน? โอน?) — ข้อมูลไม่มี อย่าเดา
- ลบบรรทัด `backfill` ทีละอัน — ปุ่มย้อนกลับล้างทั้งหมด (บรรทัดเดี่ยวลบไม่ได้ เพราะจะทำให้ยอดกับรายการไม่ตรง)

## 5. Data model

```ts
export type BankTxSource =
  // ...เดิม
  /**
   * บรรทัดที่สร้างจากยอดที่กรอกไว้ก่อนมีสมุดรายการ (F41). ไม่ได้แตะ balances
   * ตอนสร้าง — มันคือคำอธิบายของยอดที่มีอยู่แล้ว ไม่ใช่เงินก้อนใหม่.
   * ลบเดี่ยวไม่ได้ (จะทำให้ Σรายการ ≠ ยอด); ย้อนกลับทั้งชุดผ่าน undoJournalBackfill.
   */
  | { type: 'backfill' };
```

label ของบรรทัด: **"ยอดที่กรอกไว้เดิม"**

## 6. `src/utils/journalBackfill.ts` (ใหม่ · pure)

```ts
export interface BackfillLine {
  accountId: string;
  year: number;
  month: number;
  amount: number;   // ส่วนต่าง, ไม่มีวันเป็น 0
}

export interface BackfillPlan {
  lines: BackfillLine[];
  /** จำนวนเซลล์ (บัญชี×เดือน) ที่จะได้บรรทัดใหม่. */
  cellCount: number;
  /** จำนวนบัญชีที่ได้รับผลกระทบ. */
  accountCount: number;
}

/** วางแผนอย่างเดียว ไม่เขียนอะไร — UI เอาไป preview ก่อนผู้ใช้กดยืนยัน. */
export const planBackfill = (ledger: BankLedger): BackfillPlan;

/** สร้าง BankTransaction จากแผน (ต้องส่ง id เข้ามาเพื่อความ deterministic ตอนเทส). */
export const buildBackfillTransactions = (
  plan: BackfillPlan,
  makeId: (line: BackfillLine, index: number) => string,
): BankTransaction[];
```

`planBackfill` ไล่ทุก `account.balances[year][month]` เทียบกับผลรวมรายการของเซลล์นั้น ข้ามเซลล์ที่ส่วนต่างเป็น 0 (ปัดทศนิยม 2 ตำแหน่งก่อนเทียบ กันเศษ float)

**store ไม่ใช้ `applyBankMovement`** — จงใจ เพราะฟังก์ชันนั้นเขียน balances ด้วย ส่วน backfill ต้องไม่แตะ ผมจะใส่คอมเมนต์เตือนไว้ตรงนั้น ไม่งั้นคนอ่านทีหลังจะ "แก้ให้ถูก" แล้วทำยอดพัง

## 7. Store

```ts
/** เขียนบรรทัด backfill; balances ไม่ถูกแตะ. no-op เมื่อไม่มีอะไรต้องทำ. */
applyJournalBackfill: () => void;

/** ลบทุกบรรทัด source.type === 'backfill'; balances ไม่ถูกแตะเช่นกัน. */
undoJournalBackfill: () => void;
```

`deleteBankTransaction` ต้องปฏิเสธ `backfill` เพิ่มจาก income/expense/gold ที่ปฏิเสธอยู่แล้ว

## 9. Verification — `scripts/verify-journal-backfill.ts`

**กฎเหล็กที่ทุกเคสต้องผ่าน:** ยอดทุกบัญชีก่อน = หลัง (เทียบทั้ง map `balances` แบบลึก)

1. เดือนที่มียอด ไม่มีรายการ → 1 บรรทัด amount = ยอดนั้น; `findLedgerMismatches` = 0
2. เดือนผสม (ยอด 5,000 + บรรทัดทอง −100,000) → บรรทัด backfill = +105,000; invariant ผ่าน
3. เดือนที่รายการครบแล้ว (ส่วนต่าง 0) → ไม่สร้างบรรทัด
4. ยอด 0 / ไม่มี key เดือนนั้น → ไม่สร้างบรรทัด
5. **Idempotent:** รัน `applyJournalBackfill` สองครั้ง → จำนวนบรรทัดเท่าเดิม ยอดเท่าเดิม
6. `undoJournalBackfill` → บรรทัด backfill หายหมด, บรรทัดอื่นอยู่ครบ, **ยอดเท่าเดิมทุกบัญชี**
7. apply → undo → apply → ยอดและจำนวนบรรทัดกลับมาเท่าเดิม (round-trip)
8. `deleteBankTransaction` กับบรรทัด backfill → no-op
9. ยอดติดลบ (เดือนที่ถอนมากกว่าฝาก) → บรรทัด amount ติดลบ ทำงานปกติ
10. เศษทศนิยม (ยอด 711,366.21) → ไม่เกิดบรรทัดจากเศษ float
11. Export/Import round-trip เก็บ `source: {type:'backfill'}`
12. Regression: verify เดิมทั้ง 16 ตัวผ่าน (โดยเฉพาะ `verify-bank-transactions`, `verify-net-worth`)

บวก typecheck + lint + build + ขับ UI จริง: กดแปลง → กางเดือนเก่าเห็นบรรทัด "ยอดที่กรอกไว้เดิม" → แถวรวมตรงยอด → กดย้อนกลับ → กลับสู่สภาพเดิมทุกบาท
