## 1. ปัญหา — วัดจากของจริงที่ 390px

ไม่ได้เดาจาก grep — เปิดแอปจริงในกรอบ 390×844 แล้ววัด DOM ทุก route:

| อาการ | หลักฐาน |
|---|---|
| **`/monthly` เลื่อนแนวนอนทั้งหน้า** | ปุ่ม "← กลับภาพรวม" ถูกบีบเหลือกว้าง 25px แต่ข้อความล้นไปถึง x=412 บนจอกว้าง 386 → `document.scrollWidth 411 > innerWidth 386` |
| **ชื่อหน้าโดนตัดเป็น "ภา…"** | `<h1>` เหลือ 70px เพราะ header ยัดแฮมเบอร์เกอร์ + ปี + ธีม + sync + avatar ไว้แถวเดียว |
| **ปุ่มหลักหายไปบนมือถือ** | `+ เพิ่มรายการ` เป็น `hidden sm:inline-flex` — ปุ่มที่ควรกดบ่อยที่สุด ไม่มีบนเครื่องที่ควรกดบ่อยที่สุด |
| **หน้ายาวเกินไป** | ภาพรวม 3,540px (9 จอ) · วิเคราะห์ 6,628px (17 จอ) |
| **ปุ่มเล็กกว่านิ้ว** | ต่ำกว่า 40px: รายเดือน 32/45 · ทอง 24/37 · บัญชี 23/40 · วิเคราะห์ 23/34 |
| **ตารางกว้างมาก** | สรุปรายเดือน 1,000px · ภาพรวมทุกปี 1,453px ในช่องมอง 336px |
| **`/tax` ล้นนิดหน่อย** | section 361px ในช่อง 336px |

**รากของปัญหา:** แอปนี้ถูกออกแบบเป็นเดสก์ท็อป แล้ว "ทำให้ไม่พัง" บนมือถือด้วย `md:` ไม่กี่จุด (responsive prefix ใช้แค่ **55 ครั้งในทั้งโปรเจกต์**) แต่ Tom **ใช้มันบนมือถือจริง** — กรอกรายจ่ายตอนอยู่ข้างนอก, เช็คยอด, ดูตาราง/กราฟ

## 2. เป้าหมาย

ใช้ด้วยนิ้วโป้งข้างเดียวได้จริงทั้ง 3 งาน โดย **เดสก์ท็อปต้องไม่ขยับแม้แต่พิกเซลเดียว**

**Non-goal:** ไม่ออกแบบ layout ใหม่ ไม่ทำ PWA/offline ไม่ทำ swipe gesture — งานนี้คือ "เพิ่มพฤติกรรมมือถือ" ไม่ใช่ "รื้อแอป"

## 3. โครง: เมนูล่าง + ปุ่มลอย

วันนี้ nav บนมือถือคือแฮมเบอร์เกอร์ที่ **มุมซ้ายบน** — จุดที่นิ้วโป้งเอื้อมยากที่สุดบนจอ 6 นิ้ว และมันกิน 40px จาก header จนชื่อหน้าเหลือ "ภา…"

### 3.1 `src/lib/nav.ts` (ใหม่) — ทะเบียนเมนูแหล่งเดียว

วันนี้ `Sidebar.tsx` hardcode รายการเมนูไว้ในตัวเอง ถ้าเพิ่ม `BottomNav` โดยไม่แตะ จะกลายเป็นเมนูสองชุดที่หลุดจากกันวันใดวันหนึ่ง (เพิ่มหน้าใหม่แล้วลืมอีกที่)

```ts
export interface NavItem {
  path: string;      // '/monthly'
  label: string;     // 'รายเดือน'
  icon: string;      // emoji
  mobilePrimary: boolean;  // อยู่บนแถบล่าง 5 อัน หรืออยู่ใน sheet 'อื่นๆ'
}
export const NAV_ITEMS: readonly NavItem[]
export const mobilePrimaryItems(): NavItem[]   // ต้องได้ 4 เสมอ (+ 'อื่นๆ' = 5)
export const mobileMoreItems(): NavItem[]
```

pure — ไม่ import React → ทดสอบใน node ล้วนได้ (หลักเดียวกับ `lib/motion.ts`, `lib/theme.ts`)
`Sidebar` (เดสก์ท็อป) และ `BottomNav` (มือถือ) อ่านจากทะเบียนเดียวกัน

### 3.2 `BottomNav.tsx` (ใหม่) — `md:hidden`

5 แถบ: **ภาพรวม · รายเดือน · บัญชี · วิเคราะห์ · อื่นๆ**
"อื่นๆ" เปิด bottom sheet: ความมั่งคั่ง · ทองคำ · หนี้สิน · ภาษี · ตั้งค่า

- แต่ละแถบสูง ≥ 48px, มี `aria-current="page"` ที่แถบปัจจุบัน
- `padding-bottom: env(safe-area-inset-bottom)` — ไม่งั้นแถบไปอยู่ใต้แถบ home ของ iPhone
- sheet ใช้ motion primitives เดิม (`src/components/motion/`) — **ห้าม import framer-motion ตรง** (กฎ F42)

### 3.3 ปุ่มลอย "+" (FAB)

มุมขวาล่าง เหนือแถบล่าง → เปิดฟอร์ม **รายจ่าย** ตรง ๆ (งานที่ Tom ทำบ่อยที่สุดบนมือถือ)
`md:hidden` — เดสก์ท็อปยังใช้ปุ่ม "+ เพิ่มรายการ" ใน header เหมือนเดิม

### 3.4 Sidebar + Header

- `Sidebar` → `hidden md:block`. **ลบ drawer + แฮมเบอร์เกอร์ออกจากมือถือ** (เมนูอยู่ล่างแล้ว)
- `Header` บนมือถือ: ชื่อหน้าเต็ม + ปี + ปุ่มธีม + avatar. sync status เหลือไอคอน. ปุ่ม "+ เพิ่มรายการ" ซ่อน (FAB ทำแทน)

## 4. ตาราง: ตรึงคอลัมน์แรก

**ไม่แตกเป็นการ์ดรายเดือน** — CLAUDE.md วางกฎไว้แล้วว่า *"ตัวเลขในตารางมีไว้เทียบกัน"* (เหตุผลเดียวกับที่ห้ามเลขวิ่งในตาราง) การ์ดอ่านง่ายทีละเดือน แต่ **เทียบข้ามเดือนไม่ได้อีกเลย** ซึ่งเป็นเหตุผลเดียวที่ตารางนี้มีอยู่

- คอลัมน์แรก (เดือน / ปี) → `sticky left-0` + พื้น `bg-card` + เงาขอบขวาเมื่อเลื่อน
- ขอบขวาของช่องเลื่อนมี fade บอกว่า "ยังมีต่อ"
- ป้าย "เลื่อนดูคอลัมน์อื่น →" บนหัวตาราง (มือถือเท่านั้น)
- ตารางที่ต้องทำ: `MonthlySummaryTable`, `AllYearsSummary`, `LoanScheduleTable`, `PaymentLogTable`, `MultiYearComparison`

## 5. นิ้วโป้งกดโดน + ความหนาแน่น

- **พื้นที่กดขั้นต่ำ 44×44** (Apple HIG) เฉพาะ control ที่กดจริง (`button`, `a`, `select`, checkbox) — ใช้ `min-h-11 md:min-h-0` เพื่อ**ไม่ให้เดสก์ท็อปอ้วนขึ้น**
- KPI → `grid-cols-2` บนมือถือ (วันนี้เต็มความกว้าง 4 ใบซ้อน = 2 จอก่อนเจอเนื้อหา)
- กราฟเตี้ยลงบนมือถือ (`h-64 md:h-80`)
- ซ่อมของที่ล้นขอบ: ปุ่ม "← กลับภาพรวม" (`/monthly`) และ section ของ `/tax`

## 6. พิสูจน์: `npm run verify:mobile` (Playwright)

dark mode พิสูจน์ได้ด้วยการอ่านค่าสี แต่ **mobile พิสูจน์ได้จากจอที่ render แล้วเท่านั้น** — element ล้นขอบ, ปุ่มเล็กกว่านิ้ว, หน้ายาวกี่จอ วัดจาก DOM จริงทั้งหมด

เพิ่ม `@playwright/test` เป็น devDependency (ตัดสินใจแบบเดียวกับ framer-motion ใน F42: เพิ่ม dep เมื่อของที่ทำเองไม่ดีพอ)

`scripts/verify-mobile.ts` เปิดแอปที่ **390×844** แล้ววิ่งทุก route (9 หน้า) บังคับ:

| กฎ | เกณฑ์ |
|---|---|
| **M1 ไม่มีอะไรล้นขอบจอ** | `documentElement.scrollWidth ≤ innerWidth` ทุกหน้า — บาปข้อแรกของ mobile |
| **M2 ปุ่มกดโดน** | ทุก `button`/`a`/`select` ที่มองเห็น: สูง ≥ 44px **หรือ** อยู่ใน allowlist ที่มีเหตุผลเขียนกำกับ |
| **M3 แถบล่างเข้าถึงได้** | ทุก route มีแถบล่าง 5 แถบ, แถบปัจจุบันมี `aria-current="page"` |
| **M4 ตารางตรึงคอลัมน์** | ตารางกว้างเกินจอ → เซลล์แรกต้อง `position: sticky` |
| **M5 ปุ่มลอยไม่บังอะไร** | FAB ไม่ทับ control อื่น (ไม่มี element ที่กดได้อยู่ใต้มัน) |
| **M6 เดสก์ท็อปไม่ขยับ** | ที่ 1280px: ไม่มี BottomNav, ไม่มี FAB, Sidebar อยู่ครบ |

`scripts/verify-nav.ts` (pure, node ล้วน):
- `mobilePrimary` = **4 พอดี** (แถบล่าง 5 = 4 + "อื่นๆ") — เพิ่มเมนูใหม่แล้วติดธงผิด แถบจะล้น
- ไม่มี `path` ซ้ำ · ไม่มี label ซ้ำ
- ทุก item ชี้ไป route ที่ `App.tsx` มีจริง (อ่าน `App.tsx` แล้วเทียบ)

> **ไม่บังคับ "ทุก route ต้องอยู่ในเมนู"** — `/report/:year` เป็นหน้ากระดาษ (เข้าจากปุ่ม Export ไม่ใช่เมนู) และ `/installments` เป็น alias ของ `DebtPage` ตัวเดียวกับ `/loans` ถ้าบังคับ กฎจะแดงทันทีตั้งแต่วันแรกทั้งที่ไม่มีอะไรผิด

**เกณฑ์ M2 ใช้ allowlist ไม่ใช่ตัวเลขในอุดมคติ** — ปุ่มบางตัว (เช่น ✕ ปิด, ลูกศรเลื่อนเดือน) อยู่ในตารางหนาแน่นที่ 44px จะทำให้แถวสูงเกินไป ถ้าต้องยกเว้น ต้องเขียนเหตุผลกำกับในโค้ด ไม่ใช่ปล่อยเงียบ

## 7. สิ่งที่ไม่ทำโดยตั้งใจ

- **ไม่แตะ layout เดสก์ท็อป** — M6 บังคับไว้ ถ้าเดสก์ท็อปขยับ = ทำเกิน
- **ไม่แตกตารางเป็นการ์ด** — ทำลายความสามารถเทียบข้ามแถว (§4)
- **ไม่ทำ PWA / offline / swipe gesture** — YAGNI
- **ไม่ทำ responsive กับ `/report/:year`** — มันคือกระดาษ A4 สำหรับพิมพ์ ไม่ใช่หน้าจอ
