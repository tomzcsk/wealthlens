# ลบบัญชีธนาคารแล้วเงินหายเงียบ ๆ — pointer กำพร้าจาก deleteBankAccount

> สถานะ: **แก้แล้ว** (2026-07-10) — พบตอนไล่ตรวจว่า `deleteIncome` เป็นขาเดียวที่หลุดจริงไหม
> Verified: `scripts/verify-delete-bank-account.ts` (20 assertions) + UI run จริง

## อะไรพัง

`deleteBankAccount(id)` กรองบัญชีออกจาก `bankAccounts` อย่างเดียว ทั้งที่มีของ
**สี่ที่** ชี้มาหาบัญชีด้วย `accountId`:

| ต้นทาง | field |
|---|---|
| รายการเดินบัญชี | `bankTransactions[].accountId` |
| รายได้ (F39) | `income.deposits.{salary,bonus,commission,otherIncome}` + `income.depositSideEffects[].accountId` |
| รายจ่าย (F34) | `expense.paymentAccountId` + `expense.sideEffects.accountId` |
| ทองคำ (F25) | `goldHolding.sideEffects.accountId` |

ลบบัญชีแล้ว pointer เหล่านี้ค้างชี้ id ที่ไม่มีอยู่

## ทำไมถึงร้ายกว่าที่เห็น

`applyBankDelta` (`utils/bankAccounts.ts`) หาบัญชีไม่เจอก็ **คืน array เดิมเงียบ ๆ**
(`return found ? next : accounts.slice()`) ไม่ throw ไม่เตือน

ผลคือ: แก้รายได้ที่ผูกบัญชีซึ่งถูกลบไปแล้ว → modal สรุปยังบอกว่า "ฝากเงินเข้าบัญชี
+฿60,000" → กดยืนยัน → **ไม่มีบัญชีไหนได้เงิน** และไม่มี error ให้เห็น

probe ยืนยันครบ: ลบบัญชีที่มีเงินเดือนฝากอยู่ → tx ค้าง 1 บรรทัดชี้บัญชีผี,
`deposits` + `depositSideEffects` ยังชี้ id ที่ตายแล้ว, แก้รายได้ทีหลังเงินหายเงียบ

## ทางแก้: ปฏิเสธการลบ (Tom เลือก)

เส้นแบ่งที่คิดนานที่สุด — **ไม่ใช่ทุกอย่างที่ชี้มาควรบล็อกการลบ**

**บล็อก** (ต้นทางอยู่นอกบัญชี ลบแล้ว pointer ค้าง):
- รายได้ / รายจ่าย / ทองคำ
- **ขาโอน** (`source.type === 'transfer'`) — ขาคู่อยู่อีกบัญชีหนึ่ง ลบข้างเดียว
  เงินรวมทั้งระบบไม่คงที่

**ไม่บล็อก แต่กวาดทิ้งพร้อมบัญชี** (บัญชีเป็นเจ้าของบรรทัดเอง ไม่มีใครนอกบัญชีอ้าง):
- `manual` / `adjustment` / **`backfill`**

`backfill` สำคัญเป็นพิเศษ: รายการเดินบัญชีทั้ง 32 บรรทัดในข้อมูลจริงของ Tom เป็น
backfill ล้วน (F41) ถ้านับเป็นตัวบล็อก **เขาจะลบบัญชีไหนไม่ได้เลยตลอดกาล** —
ตรึงไว้ในเทสต์ชื่อ "บัญชีเก่า (ยอด + backfill) → ลบได้"

## รูปร่างของโค้ด

- `utils/bankAccountUsage.ts` (ใหม่, pure): `findBankAccountUsage` / `isBankAccountDeletable`
- `actionMessages.ts` (ชั้นข้อความเดิมจาก F43): `bankAccountBlockedReason` — บอกเฉพาะ
  หมวดที่ผูกอยู่จริง หมวดที่เป็น 0 ไม่โผล่ในประโยค (หลักการเดียวกับ `withSideEffect`)
- `financeStore.ts`: guard ใน action (กันเส้นทางที่เรียกตรง) + กวาด `bankTransactions`
  ของบัญชีนั้นเมื่อลบได้
- `BankAccountsPage.tsx`: modal เปลี่ยนเป็นโหมดอธิบาย เหลือปุ่มเดียว "เข้าใจแล้ว"

## ที่ไม่ทำโดยตั้งใจ

- **ไม่มี cascade delete** — ลบบัญชีแล้วไล่ลบรายได้/รายจ่ายที่ผูกอยู่ให้อัตโนมัติ
  คือการทำลายข้อมูลการเงินจริงจากการกดปุ่มเดียว ผู้ใช้ต้องถอดการผูกเองก่อน
- **`applyBankDelta` ยังทิ้งคีย์ยอดศูนย์** (`{"2027": {"7": 0}}`) เมื่อ revert จนยอดเป็น 0
  ไม่ทำให้ตัวเลขไหนผิด (ศูนย์คือศูนย์ ไม่กระทบ KPI/Net Worth/ผลรวม) และเป็นพฤติกรรม
  ที่มีมาก่อนงานนี้ทุกเส้นทาง (`updateIncome` ถอน deposits, ลบรายจ่ายที่หักบัญชี)
  แก้ที่ `applyBankDelta` = แตะจุดที่ทุก flow เรียกผ่าน — เสี่ยงเกินผลตอบแทน Tom ตัดสินให้ปล่อยไว้
