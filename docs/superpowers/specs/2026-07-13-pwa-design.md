# F51 — PWA (ติดจอมือถือ + เปิดได้ไม่มีเน็ต)

**วันที่:** 2026-07-13
**สถานะ:** design approved — รอ plan
**Phase:** 6 (งานที่ 3 จาก 3: หนี้เทคนิค ✅ → รื้อหน้าวิเคราะห์ ✅ → **PWA**)

---

## 1. ครึ่งหนึ่งของงานนี้ ทำไว้แล้ว

ตรวจของจริงก่อนออกแบบ:

| | สถานะวันนี้ |
|---|---|
| **ข้อมูลอยู่ในเครื่อง** | ✅ LocalStorage-first ตั้งแต่ F02 — อ่าน/เขียนไม่ต้องใช้เน็ตอยู่แล้ว |
| **รู้ตัวว่าออฟไลน์** | ✅ `useDriveSyncCoordinator` ฟัง event `online`/`offline` แล้ว (`syncStore` มีสถานะ `'offline'`) |
| **กลับมาออนไลน์แล้ว sync ต่อ** | ✅ มี — ดันข้อมูลขึ้น Drive ใหม่เพื่อ converge หลังแก้ตอนออฟไลน์ (`useDriveSyncCoordinator.ts:226`) |
| **เปิดแอปตอนไม่มีเน็ต** | ❌ **เปิดไม่ได้** — ไฟล์แอปยังต้องโหลดจาก network |
| **ติดจอโฮม** | ❌ ไม่มี manifest · ไม่มีไอคอน PWA (มีแต่ `favicon.svg`) |
| **`<title>`** | ❌ `wealthlens` (ตัวเล็ก) |

**งานจริงจึงเหลือแค่สองอย่าง:** ทำให้ *เปิดได้ตอนไม่มีเน็ต* และ *ติดจอโฮมได้*

## 2. เป้าหมาย

Tom กดไอคอน WealthLens บนจอโฮมของมือถือ **ตอนอยู่ใต้ดิน/บนเครื่องบิน** แล้วแอปเปิดขึ้นมา ดูยอดได้ กรอกรายจ่ายได้ — พอกลับมามีเน็ต มันซิงค์เอง

**Non-goal:** ไม่ทำ push notification · ไม่ทำ background sync API · ไม่แตะชั้นข้อมูล/ซิงค์ที่ทำงานดีอยู่แล้ว

## 3. ทำอะไรบ้าง

### 3.1 ติดจอโฮม

- `public/manifest.webmanifest` — `name: "WealthLens"`, `short_name: "WealthLens"`, `start_url: "/"`, `display: "standalone"`, `theme_color`, `background_color`
- **ไอคอน 192 + 512 + maskable** สร้างจาก `public/favicon.svg` ที่มีอยู่ (โลโก้สายฟ้าม่วง `#863bff`) โดย **rasterize ด้วย Playwright ที่ติดตั้งอยู่แล้ว** — ไม่เพิ่ม dependency เพื่อทำรูป
  maskable ต้องมี safe area (โลโก้อยู่ใน 80% ตรงกลาง) ไม่งั้น Android จะครอบมุมโลโก้ทิ้ง
- `apple-touch-icon` + `apple-mobile-web-app-capable` + `apple-mobile-web-app-status-bar-style` — **iOS ไม่อ่าน manifest ครบ** ต้องใส่ meta แยก
- `<title>` → `WealthLens`
- **`theme-color` สองค่า** (`media="(prefers-color-scheme: dark)"`) — ไม่งั้นแถบสถานะบนมือถือจะขาวโพลนคาดอยู่บนหัวแอปโหมดมืด

### 3.2 เปิดได้ตอนไม่มีเน็ต

Service worker ผ่าน **`vite-plugin-pwa`** (devDependency, ใช้ workbox)

> **ทำไมไม่เขียน SW เอง:** cache invalidation คือกับดักคลาสสิกของงานนี้ — พลาดแล้วผู้ใช้ **ติดอยู่กับแอปเวอร์ชันเก่าถาวร** และ debug ยากมาก (โค้ดถูก แต่เบราว์เซอร์เสิร์ฟของเก่า) นี่ไม่ใช่ที่ที่ควรประหยัด dependency
> ตรงกับจุดยืนเดิมของโปรเจกต์ (F42: เพิ่ม framer-motion เพราะของที่ทำเองไม่ดีพอ)

precache: `index.html` + JS/CSS/ฟอนต์/ไอคอน + โลโก้ธนาคาร 23 ไฟล์

### 3.3 อัปเดต — กับดักที่ใหญ่ที่สุด

พอมี SW แล้ว push ขึ้น Vercel → เปิดมือถือ → **ยังเห็นแอปเวอร์ชันเก่า** เพราะ SW เสิร์ฟจาก cache

`registerType: 'prompt'` → มี SW ใหม่รออยู่ → เด้ง **toast "มีเวอร์ชันใหม่ — แตะเพื่ออัปเดต"** ผ่าน `Toaster` เดิม (ไม่สร้าง UI ใหม่) แตะแล้ว `skipWaiting()` + reload

**ทำไมไม่อัปเดตเงียบ ๆ:** reload กลางคันตอนกำลังกรอกฟอร์ม = ข้อมูลที่พิมพ์ค้างหาย

## 4. สามเส้นที่ห้ามข้าม

1. **`/api/gold-price` ห้ามถูก cache** → `NetworkOnly`
   มันคือราคาทองสด ถ้า SW แช่ไว้ Tom จะเห็นราคาเมื่อวานโดยไม่รู้ตัว — และ net worth จะคำนวณจากราคานั้น
2. **Google Drive / OAuth ห้ามถูก cache** → `NetworkOnly`
   token กับ response ที่ค้างใน cache คือทั้งบั๊กและความเสี่ยง
3. **ห้ามโกหกเรื่องสถานะ** — ออฟไลน์ = อ่าน/เขียนได้ (LocalStorage) แต่ **ซิงค์ไม่ได้**
   `syncStore` มีสถานะ `offline` อยู่แล้ว ต้องไม่แสดงว่า "ซิงค์แล้ว" ตอนที่ไม่ได้ซิงค์

**SW ไม่แตะข้อมูลการเงินอยู่แล้ว** (มันอยู่ LocalStorage ซึ่ง SW เข้าไม่ถึง) — แต่ต้อง **พิสูจน์** ว่าไม่มีอะไรของ Drive ติดอยู่ใน cache storage (P5)

**dev ต้องไม่โดน SW กวน** — `devOptions.enabled: false` ไม่งั้นแก้โค้ดแล้วไม่เห็นผลจนกว่าจะ hard-reload

## 6. สิ่งที่ไม่ทำโดยตั้งใจ

- **ไม่ทำ push notification** — ต้องมี server กลาง ซึ่งชนหลักการข้อ 1 ของโปรเจกต์ (ไม่มี backend)
- **ไม่ทำ Background Sync API** — `useDriveSyncCoordinator` ซิงค์ตอนกลับมาออนไลน์อยู่แล้ว การเพิ่ม Background Sync คือความซับซ้อนที่ไม่ได้อะไรเพิ่ม
- **ไม่แตะชั้นซิงค์** — มันทำงานถูกอยู่แล้ว งานนี้แค่ทำให้ *ตัวแอป* เปิดได้ตอนไม่มีเน็ต
- **ไม่ cache ข้อมูลจาก Drive ไว้อ่านออฟไลน์** — LocalStorage เป็นแหล่งความจริงของเครื่องนี้อยู่แล้ว การมี cache ชั้นสองของข้อมูลเดียวกัน = สองแหล่งความจริงที่จะไม่ตรงกันวันหนึ่ง
