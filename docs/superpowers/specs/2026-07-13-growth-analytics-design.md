## 1. คำถามที่แอปยังตอบไม่ได้

วันนี้แอปมี: pie ตามหมวด · รายรับ-รายจ่ายรายเดือน · เทียบข้ามปี · เทรนด์ 48 เดือน · จับรายจ่ายผิดปกติ · พยากรณ์งบ · subscription · **ความมั่งคั่ง (ภาพนิ่ง ณ วันนี้)** · ภาษี

สองคำถามที่ยังตอบไม่ได้ และมันคือสต็อกกับโฟลว์ของเรื่องเดียวกัน:

| คำถาม | วันนี้ | ทำไมสำคัญ |
|---|---|---|
| **"รวยขึ้นหรือเปล่าลง?"** | `/wealth` บอกได้แค่ **ตัวเลข ณ วันนี้** — F38 เขียนไว้ตรง ๆ ว่า *"กราฟ net worth ย้อนหลัง = นอก scope"* | ตัวเลขเดี่ยว ๆ ไม่มีความหมาย ถ้าไม่รู้ว่ามันมาจากไหน |

## 3. ความจริงของข้อมูล (ตรวจจากข้อมูลจริงของ Tom ก่อนออกแบบ)

### 3.1 `balances[ปี][เดือน]` คือ **กระแสเงินของเดือนนั้น** ไม่ใช่ยอดคงเหลือ

ตรวจแล้วจากโค้ด: `accountAllTimeTotal()` บวกทุกเดือนเข้าด้วยกัน และการ์ดบัญชีเขียนว่า "ยอดสะสมทุกปี" ตรงกับ invariant ของ F40: *ทุก (บัญชี, ปี, เดือน) ที่มีรายการ → Σ tx.amount === balance*

**ผลต่อการออกแบบ:** ยอดบัญชี ณ เดือน M = **ผลรวมสะสมของทุกเดือน ≤ M**
เดือนที่ไม่มีตัวเลข = เดือนที่เงินไม่ขยับ → ยอดคงเดิมอยู่แล้วโดยธรรมชาติ

> รอบแรกผมออกแบบกฎ "carry-forward ยอดล่าสุด" เพราะเข้าใจว่าเป็นยอดคงเหลือ — **ผิด**. กฎนั้นไม่ต้องมี และการเข้าใจผิดข้อนี้จะทำให้กราฟผิดทั้งเส้น (ยอดจะแบนราบแทนที่จะสะสม)

### 3.2 ข้อมูลจริงของ Tom (นับจาก LocalStorage)

| | ของจริง |

| **กรุงศรี Kept** | 27 เดือนติดกัน (2024-05 → 2026-07) ไม่มีช่องโหว่ |
| **clicx · กสิกรไทย · กรุงศรีอยุธยา · กรุงไทย · เงินสด** | **มีตัวเลขแค่ 1–2 เดือน** — เริ่มติดตาม 2026-07 |

## 4. กฎไม่ให้กราฟโกหก (หัวใจของงานนี้)

### กฎ 1 — ยอด ณ เดือน M = ผลรวมสะสมถึงเดือน M
บัญชี · เงินออม · ทอง (เฉพาะที่ซื้อก่อน M) ล้วนสะสม. หนี้ใช้ `getPrincipalRemaining(loan, วันสิ้นเดือน M)` ซึ่งรับ `referenceDate` อยู่แล้ว (F36)

### กฎ 2 — "เริ่มติดตามบัญชีใหม่" ต้องไม่ถูกอ่านว่า "รวยขึ้น"
ก.ค. 2026 มี 5 บัญชีโผล่พร้อมกัน (เงินสด ฿150,000 ฯลฯ) กราฟจะกระโดด **ทั้งที่เงินนั้นมีอยู่มาตลอด Tom แค่เพิ่งเริ่มบันทึก**

1. **ปักหมุดบนกราฟ** ที่เดือนนั้น + ป้าย "เริ่มติดตาม: เงินสด, กสิกรไทย, …"
2. **ช่วงก่อนหน้าวาดเป็นเส้นจาง** + ป้ายบอกว่าครอบคลุมกี่บัญชี
3. **% เติบโตที่คร่อมจุดกระโดด → ไม่แสดงตัวเลข** แสดง "เทียบไม่ได้ (เริ่มติดตามบัญชีใหม่)" แทน. โชว์ +38% ทั้งที่มันคือการเปลี่ยนวิธีนับ = โกหกด้วยตัวเลขจริง

### กฎ 3 — "ไม่มีข้อมูล" ≠ "เป็นศูนย์"
ปี 2023 ไม่มีรายจ่าย → savings rate **ไม่ใช่ 100%** แต่คือ `null` → ไม่วาดแท่ง + caption บอกว่าไม่มีข้อมูลรายจ่าย
(ถ้าปล่อยไว้ ปี 2023 จะกลายเป็นปีที่ "ออมเก่งที่สุด" ในกราฟ ทั้งที่มันคือปีที่เรารู้น้อยที่สุด)

ทองที่ยังไม่ตั้งราคาตลาด → ใช้ราคาทุน + ธง `isCostBasis` (F38 ทำไว้แล้ว ใช้ต่อ)

### กฎ 4 — ไม่มี insight ปลอม
ไม่มีข้อความประเภท *"คุณออมได้ดีกว่า 80% ของคนวัยเดียวกัน"* — เราไม่มีข้อมูลนั้น ไม่มีสิทธิ์พูด

## 5. สถาปัตยกรรม

### `src/utils/netWorthHistory.ts` (ใหม่, pure)

```ts
export interface NetWorthPoint {
  ym: string;                 // '2025-07'
  assets: number;
  debts: number;
  netWorth: number;           // ติดลบได้ ห้าม clamp (กฎเดิม F38/F44)
  accountsCovered: number;    // กี่บัญชีที่มีข้อมูลถึงเดือนนี้
  isTrackingJump: boolean;    // เดือนนี้มีบัญชีใหม่โผล่ครั้งแรก
  newAccounts: string[];      // ชื่อบัญชีที่เพิ่งเริ่มติดตามเดือนนี้
  goldIsCostBasis: boolean;
}

export const buildNetWorthHistory = (
  data: WealthLensData,
  goldPriceAt: (ym: string) => number | null,   // ราคาทอง/บาท ณ เดือนนั้น (null = ไม่รู้)
  resolvedLoans: readonly Loan[],
  installmentPlans: readonly InstallmentPlanSummary[],
): NetWorthPoint[];

/** % เติบโตเทียบเดือนก่อน — null เมื่อคร่อมจุดกระโดด (กฎ 2) */
export const growthBetween = (
  from: NetWorthPoint, to: NetWorthPoint,
): number | null;
```

## 7. สิ่งที่ไม่ทำโดยตั้งใจ

- **ไม่พยากรณ์ net worth อนาคต** — มี `BudgetForecast` (F16) อยู่แล้วสำหรับรายจ่าย; ยัดเส้นทำนายความมั่งคั่งเข้าไปคือการเดาที่ดูน่าเชื่อถือเกินจริง
- **ไม่เทียบกับใคร** (กฎ 4)
- **ไม่แตะ `/wealth`** — มันตอบ "วันนี้เท่าไร" ได้ดีอยู่แล้ว หน้าใหม่ตอบ "มาถึงตรงนี้ได้ยังไง"
- **ไม่ทำ cashflow เข้า-ออกบัญชี** — เป็นคำถามที่สามที่ Tom ไม่ได้เลือก
