## 1. ปัญหา — วัดจริงที่ 390px

`/analytics` สูง **6,584px = 7.8 จอ** บนมือถือ (5,433px บนเดสก์ท็อป) เพราะมัน **เอาเครื่องมือ 6 อย่างคนละเรื่องมากองซ้อนกันในหน้าเดียว**

| แผง | สูง | สัดส่วน |
|---|---:|---:|
| แจ้งเตือนผิดปกติ (F15) | 1,624px | 25% |
| แนวโน้ม 48 เดือน + สัดส่วนค่าใช้จ่าย (F14) | ~1,724px | 26% |
| Subscription รายเดือน (F12) | 1,197px | 18% |
| เทียบข้ามปี + สรุปรายปี (F10) | 1,130px | 17% |
| ประมาณการเดือนหน้า (F16) | 756px | 11% |
| ตารางภาพรวมทุกปี | 532px | 8% |

**แต่ละแผงยาวสมเหตุผลของมัน — ปัญหาคือมันไม่ควรอยู่หน้าเดียวกันตั้งแต่แรก** Tom เปิดหน้านี้เพื่อดู *อย่างหนึ่งที่ตั้งใจ* แล้วต้องเลื่อนผ่านอีก 5 อย่างที่ไม่ได้ตั้งใจดู

**และ 36% ของหน้า (2,380px) คือของที่ไม่เคยดูเลย** — แจ้งเตือนผิดปกติ (F15) กับ ประมาณการเดือนหน้า (F16) ทั้งคู่มาจาก Phase 3

## 2. เป้าหมาย

เปิดหน้าวิเคราะห์แล้วเจอสิ่งที่ตั้งใจดู **ภายในหน้าจอเดียว** ไม่ต้องเลื่อนผ่านของคนอื่น

**Non-goal:** ไม่เพิ่มการวิเคราะห์ใหม่ · ไม่แตะสูตรคำนวณใด ๆ · ไม่แตะหน้าอื่น

## 3. ตัดของที่ไม่มีใครดู

การลบฟีเจอร์คือการทำลายของ — เขียนให้ชัดว่าอะไรหาย อะไรอยู่ และ **บันทึกในประวัติว่าเคยมีแล้วถอดออก ไม่ใช่แกล้งทำเป็นไม่เคยมี**

### 3.1 ประมาณการเดือนหน้า (F16) — ลบทั้งฟีเจอร์

เห็นได้ที่หน้านี้ที่เดียว ไม่มีช่องทางอื่น และ Tom ไม่เคยดู → ฟีเจอร์ที่ไม่มีใครใช้ คือโค้ดที่ต้องดูแลตลอดไปโดยไม่ได้อะไรตอบแทน

**ลบ:** `components/analytics/BudgetForecast.tsx` (360) · `hooks/useForecast.ts` · `utils/forecast.ts`

### 3.2 แจ้งเตือนผิดปกติ (F15) — เก็บ toast ตัดแผง

**ข้อเท็จจริงที่ตรวจแล้ว:** `useAnomalyAlertEffect` (mount ที่ `Layout`) เด้ง toast เองเมื่อเจอรายจ่ายผิดปกติใหม่ — มันมีชุด "seen" แบบ session-local ของตัวเอง **ไม่ได้พึ่งแผงเลย** ส่วน `anomalyStore` (การกดปิดถาวร) **ถูกใช้โดยแผงเท่านั้น**

→ ตัดแผง toast ยังทำงานครบ

**ลบ:** `components/analytics/AnomalyAlerts.tsx` (300) · `stores/anomalyStore.ts` (ตายทันทีที่แผงหาย — ไม่มีที่ให้กดปิดอีกต่อไป)
**เก็บ:** `hooks/useAnomalies.ts` · `hooks/useAnomalyAlertEffect.ts` · `utils/anomalyDetection.ts` — ถอดตัวกรอง "รายการที่กดปิดแล้ว" ออกจาก `useAnomalies` เพราะไม่มีที่ให้กดปิดแล้ว

**LocalStorage key `wealthlens_anomaly_dismissals` กลายเป็นขยะกำพร้า** — ไม่ลบ ไม่แตะ มันไม่อยู่ใน Drive payload และไม่มีใครอ่าน. เขียนไว้ให้รู้ ดีกว่าเขียนโค้ดลบ key ที่ต้องดูแลต่ออีกสิบปี

### 3.3 บันทึกประวัติให้ตรง

`features.json`: **F15** → *"เหลือ toast แผงถูกถอด (F50)"* · **F16** → `status: "removed"` พร้อมเหตุผล
ประวัติต้องบอกความจริงว่ามันเคยมี ใครมาอ่านทีหลังจะได้ไม่สร้างซ้ำ

## 4. สามแท็บ แทนกองซ้อน

`/analytics?tab=…` — **สถานะอยู่ใน URL** ปุ่มย้อนกลับใช้ได้ · บุ๊กมาร์กได้ · ส่งลิงก์ตรงแท็บได้ (state ใน `useState` ทำสามอย่างนี้ไม่ได้สักอย่าง)

| แท็บ | `?tab=` | มีอะไร | สูงโดยประมาณ |
|---|---|---|---|
| **รายปี** (ค่าเริ่มต้น) | `years` | ตารางภาพรวมทุกปี + เทียบข้ามปี + สรุปรายปี | ~1,662px |
| **แนวโน้ม** | `trends` | 48 เดือน + สัดส่วนค่าใช้จ่ายตลอดเวลา | ~1,724px |
| **Subscription** | `subs` | รายการ + ยอดรวมรายเดือน | ~1,197px |

`?tab=` ที่ไม่รู้จัก → ตกกลับไปแท็บ `years` (ไม่ใช่หน้าว่าง)

**แต่ละแท็บ lazy-load** (`React.lazy`) — วันนี้เปิด `/analytics` ครั้งเดียวโหลด Recharts ของทั้ง 6 แผง ทั้งที่ดูอันเดียว. lazy จริง ไม่ใช่ซ่อนด้วย CSS — **แผงของแท็บอื่นต้องไม่อยู่ใน DOM เลย** (§5 บังคับไว้)

**ผลลัพธ์: 7.8 จอ → ~2 จอต่อแท็บ**

### แถบแท็บ
- เดสก์ท็อป: pill row ใต้หัวหน้า
- มือถือ: pill row เลื่อนแนวนอนได้ · แต่ละแท็บ ≥ 44px (กฎ F47) · แท็บปัจจุบัน `aria-current="page"`

## 5. พิสูจน์

### `scripts/verify-analytics.ts` (Playwright ที่ 390×844)

| # | กฎ | จับอะไร |
|---|---|---|
| **A1** | ทุกแท็บสูง **≤ 2,200px** | เป้าหมายทั้งงาน — ถ้าเกิน แปลว่ายังกองซ้อนอยู่ |
| **A2** | เปิดแท็บหนึ่ง → **DOM ต้องไม่มีแผงของแท็บอื่นเลย** | "lazy" ที่จริง ๆ แค่ `hidden` — โหลดครบเหมือนเดิม แค่มองไม่เห็น |
| **A3** | `?tab=trends` เปิดตรงแท็บนั้น · `?tab=ขยะ` ตกกลับ `years` ไม่ใช่หน้าว่าง | URL เป็นแหล่งความจริงจริงไหม |
| **A4** | ปุ่มแท็บทุกตัว ≥ 44px · แท็บปัจจุบันมี `aria-current` | กฎ F47 |
| **A5** | ไม่มีอะไรล้นขอบจอ | กฎ F47 (M1) |

### ประตูกันซาก (`verify-analytics.ts`, node ล้วน)
- ไม่มีไฟล์ไหนใน `src/` import `BudgetForecast` · `useForecast` · `utils/forecast` · `AnomalyAlerts` · `anomalyStore`
- ไฟล์ทั้ง 5 นั้น **ไม่มีอยู่จริง** (โค้ดตายที่ยังอยู่ = วันหนึ่งมีคน import กลับมา)

### toast ต้องไม่ตายไปกับแผง
- `Layout.tsx` ยังเรียก `useAnomalyAlertEffect()` · `useAnomalies` ยังคืนรายการได้
- **ขับจริง:** ยัดรายจ่ายผิดปกติเข้าไปหนึ่งรายการ → toast ต้องเด้ง (นี่คือคุณค่าเดียวที่เหลือของ F15 — ถ้ามันตายไปด้วย แปลว่าตัดผิด)

### เดิมต้องไม่พัง
verify ทั้ง 31 ตัว + `verify:mobile` (10 หน้า) + typecheck + lint + build

## 6. สิ่งที่ไม่ทำโดยตั้งใจ

- **ไม่แยกเป็นหลายหน้าในเมนู** — เมนูมี 9 รายการแล้ว แท็บในหน้าเดียวคือขอบเขตที่ถูกต้องของ "เครื่องมือวิเคราะห์"
- **ไม่ลบ LocalStorage key เก่า** (§3.2)
- **ไม่แตะสูตรคำนวณ** ของแผงที่เหลือ — งานนี้คือ "จัดที่ทาง" ไม่ใช่ "แก้เลข"
- **ไม่เพิ่มการวิเคราะห์ใหม่** — F48 เพิ่งเพิ่มหน้าเติบโตไป
